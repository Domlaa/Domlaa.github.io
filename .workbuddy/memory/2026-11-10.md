## MK7 拆解效果重构（用户反馈「像被撕烂」）

### 根因
- armor2.glb 是**单块蒙皮网格**，没有部件层级；旧方案用**直线平面**（模板阈值 t/|x|/z）逐三角形分类。
- 直线切分穿过连续甲片，且按三角形质心离散化 → 断口呈锯齿状、甲片被拦腰切断（旧图可见背部金色壳体被垂直切出直边）。

### 新方案（js/showcase7/segment.js 阶段 4 重写）
1. **顶点焊接**：量化位置（容差 height*5e-5 ≈0.1mm）消除 UV 缝/硬边产生的重复顶点。
2. **连通域洪水填充**：共享边建边→三角邻接表，BFS 得到 380 个「岛屿」（整块甲片）。
3. **整岛归属**：三角形按旧直线规则投票，一致率 ≥0.8 → 整岛归多数区域（333 个岛走这条路，甲片不再被切）。
4. **跨区域大岛**（47 个，连续壳体）：ICM 折痕寻路细化标签，
   `E = Σ[标签≠直线规则]·0.45 + Σ β(折痕)·[两端不同]`，`β = 1 - 0.97·min(1, crease/0.6)`，
   让断口贴甲片分模线（实测只挪动 243 个三角形，说明沟槽浅，但仍比硬切平整）。

### 实测
- 380 岛 / 333 整岛 / 47 切开；最大岛 3224 三角形；总三角数 142,622 不变。
- 三处仍必须切开的连续壳体：颈肩（2386）、躯干整圈壳体（1712）、髋与大腿（1316×2）。
- 髋部那些「尖刺」在组装状态下也存在，是模型自带的护甲叠层，不是切割产物。
- 手臂外侧那条细长片是模型自带的独立窄板（原属 armR），不是碎片。
- 模型加载+切分 2.1–2.6s；1440×900@2x 下 FPS 59–68（含用户新加的 3D 背景）。

### 顺手修的两个手机端问题（背景按钮导致 9 个控件）
- `.tb-row` 手机端网格 4 列 → 3 列（9 个控件刚好 3×3，不再出现单按钮独占一行、宽度不齐）。
- `frameCamera` 的 safeBottom 改为**测量工具栏实际高度**（`innerHeight - toolbar.getBoundingClientRect().top + 16`），
  并放开窄屏垂直位移上限到 0.22H；脚部不再被面板遮住。

### 结论（回答用户）
不是模型「不支持拆解」，而是单网格 + 直线切分的问题。真正的「整件卸下」需要模型本身有分离的部件层级
（或手工标注拆解缝线）；当前能做到的是让切口沿几何缝隙走，不再切穿甲片。

## 集成 HALOFLUX 贾维斯背景到 mk7（用户 @haloflux/）

### haloflux 结构分析
- 纯原生 Canvas 单文件：`lab.html`（桌面）/`mobile.html`（移动）/`wallpaper/index.html`（壁纸版，无鼠标 UI）。
- 核心：节拍时钟驱动 —— 圈内网线（web）、数据块圆环（cards/slots）、环外伸缩光束 5 层、飞出流线、bokeh、相机 7 段运镜。
- 56 个可调参数 `PARAM`，`setParam(k,v,silent)` 全局函数；`wallpaperPropertyListener.applyUserProperties()` 供壁纸引擎驱动；`window.__wpPaused` 暂停渲染循环；`window.__bgm.{set,setVol,kick}`。
- 许可：PolyForm Noncommercial 1.0.0，必须署名 "HALOFLUX by Ryder191"。

### 集成方案（iframe + 透明画布）
- 用**壁纸版**做 `<iframe id="jarvis">`，z-index 0 置于 WebGL 画布（z-index 1）之下，pointer-events:none。
- 同源 → 直接 `contentWindow` 调 `applyUserProperties({showui:false, camera:false, tempo:.5, ringspeed:.42, beamglow:2.2})`；
  再 `setParam` 关掉最贵的 canvas filter：`depthBlur:0 / webBlur:0`，并把 `runnerCount:260 / hazeCount:10 / flyerCount:1`。
- 注入 `<style>.ov{display:none}</style>` 去掉它舞台上的英文仪表文字（和装甲页 HUD 语义无关）。
- **关键坑：`scene.background = new THREE.Color()` 会让 three 清屏强制 alpha=1**（`setClear(background,1)`），
  覆盖 `setClearColor(…, 0)` 的 clearAlpha —— 于是 RT 背景 alpha 一直是 1，透明输出无效，画布始终不透明。
  删掉 scene.background、改用 `renderer.setClearColor(0x0a0e13, 0)` 后透明才成立（也顺带修好了原本就没生效的 alpha 遮罩）。
- 合成通道加 `uTransparent`：`outA = mix(1.0, mask, uTransparent)`，`mask = tColor.a`；贾维斯模式=1 → 透传 RT alpha。
  渲染器改为 `{ alpha:true, premultipliedAlpha:false }`。
- 性能：iframe 用 **40% 尺寸 + scale(2.5)**（内部只渲染约 16% 像素再放大）；
  另用 `setInterval(16ms)` 隔帧设 `__wpPaused`，把 HALOFLUX 压到 ~30fps。
  实测 DPR1 90fps（不降），DPR2 从 81-90 降到 53-61fps。
- 观感：#jarvis opacity .62 + `#jarvisveil` 径向聚光遮罩（中心压暗给装甲让位），光环留在四周。
- 交互：`贾维斯` 按钮 / `J` 切换（触屏默认关）；开贾维斯自动关程序化背景、关时恢复；
  `M` 切 HALOFLUX 自带 BGM（`__bgm.kick()`）；首次加载推迟到模型就绪后 600ms（不与 38MB 模型抢带宽）；
  加载失败自动回退 3D 背景。截图导出会把 iframe 的 stage canvas 一起合成进去。
- 署名：mk7.html 顶部许可注释 + 页面底部 `贾维斯背景：HALOFLUX by Ryder191 · PolyForm NC`。

## 压缩模型（draco + webp）可行性验证 → mk7-tiny.html

用户把两个 `npx @gltf-transform/cli optimize --compress draco --texture-compress webp` 压缩后的 GLB 放进 `model/tiny/`，
要求单独建测试页验证能否替换 MK7 渲染（不改既有页面）。

### 基础设施
- 本地化 Draco 解码器：从 `npm pack three@0.187.0` 提取（unpkg 直连 SSL 失败，registry 可达）
  → `lib/three/addons/libs/draco/{draco_decoder.js,draco_decoder.wasm,draco_wasm_wrapper.js}` + `loaders/DRACOLoader.js`。
- `main.js`：`new GLTFLoader(manager).setDRACOLoader(new DRACOLoader(manager).setDecoderPath('./lib/three/addons/libs/draco/'))`
  —— 非 draco 模型走原路径，行为不变。
- 参数覆盖（默认值下原页面零影响）：`?model=` / `data-model` 覆盖 `CONFIG.url`；`?fit=` / `data-fit` 覆盖 `CONFIG.fitScale`。

### 踩到的坑
- **ES module 里 `document.currentScript` 恒为 `null`**，读 `data-model` 必须先 `document.querySelector('script[type="module"][data-model]')`。
  一开始用它取 data-model 没报错但静默走默认模型（表现：加载 38MB armor2 而不是 6MB 压缩包），用网络面板的 modelMB 才发现。
- **`segment.js` 属性合并取首个源属性名**：gltf-transform 会裁掉各 primitive 未用属性，`d.maps[name]` 为 undefined → `Cannot read properties of undefined (reading 'arr')`。
  改为按**并集**合并、缺失源补 0（原模型属性一致时结果不变）。

### 两个模型的结构对比（python 解析 GLB JSON chunk）
| | armor2.glb（现用） | irobny2_optimized | hulk+buster2_optimized |
|---|---|---|---|
| 体积 | 38.00 MB | 5.45 MB (−86%) | 6.62 MB (−83%) |
| materials | 3 | 3（同名 Material.001/.003/.004 + none） | **15** |
| images | 5 PNG | 5 webp | 17 webp |
| meshes | 16 | 4 | 73（three 展开 117） |
| 主 mesh tris | 142,622 | 90,543 | 323,384（15 材质分散） |
| skins/anims | 3/3 | 1/3 | 0/0 |

### 结论
- ✅ 压缩格式本身没问题：`EXT_texture_webp` + `KHR_draco_mesh_compression` three r187 原生支持，几何无损（三角形与原模型一致），
  irobny2 加载 1.1s / 90 FPS / 拆解 7 模块全部正常，视觉与原版几乎无差。
- ✅ irobny2_optimized 可**直接替换** armor2（材质结构一致，同一战甲的轻量版）。
- ⚠️ hulk+buster2 是**反浩克**（宽体，bbox X 1.85 / Y 1.95 / Z 1.39，需 `fit=1.3` 才不裁切），
  且 15 种材质会被 `segment.js:377 material: bucket.tris[0].src.mesh.material` 按「首个三角形材质」压成单材质
  → 大片错贴图（左半身纯黑、右半身银灰）。要用必须改为按材质分组切分（每 region 每材质一个 mesh）。
- 回归：mk7.html（142,622 tris / 90 fps / fit 3.88 / 拆解 7）、mk7-console、ironman-hud 全部正常 0 错误。
- 站点长期 404：浏览器自动请求 `/favicon.ico`（站点无此文件，与本次无关）。

## ironman-hud 升级：压缩模型线稿 + 3D 背景 + 控制面板

用户判断：压缩 GB 只适合线条（表面细节缺失，表面还是原版好）。要求 HUD 页用优化模型、仅线条、加控制面板、并把 mk7 的 3D 背景搬过来。

### 关键坑：加色背景在透明画布上完全不可见
- mk7 的 3D 背景元素是 `PURE_ADD`（AdditiveBlending），片元显式输出 `alpha = 0.0`；
  additive 的 alpha 方程 = srcAlpha² + dstAlpha = 0 → 透明画布上整层背景被丢弃。
  （`setBackground()` 的注释早写过「透明画布画不出程序化背景」，这次才真正踩到。）
- 解法：iframe 加 `solid=1` → `uTransparent = 0`（不透明输出，背景才有 alpha）；
  宿主 `#armor-frame { mix-blend-mode: screen }` 把 0x0a0e13 深色底筛成透明，
  光柱/地面网格/粒子叠到 HUD 玻璃层上，装甲暗部自动透出 → 反而更像全息投影。

### main.js 的 embed 参数化（全部默认关闭，旧嵌入行为不变）
`embed=1` 后可选：`panel=1`（显示工具栏）、`bg=1`（3D 背景）、`line=1`（仅线条）、
`auto=1`（自动旋转）、`solid=1`（不透明输出）。
- `frameCamera`：`state.embed && !state.embedPanel` 才用「视口即取景框」，否则走实测工具栏的 safeBottom 分支。
- `line=1` 在 `initUI()` 之后调 `setLineOnly(true)`，顺带同步按钮 on 与表面滑条 disabled。

## 扫描环配色改造（提交 1d41bfc）
- **重要发现**：`edgeMat` 合成通道里 `uSurface=0`（仅线条模式）会把整幅 3D 画面
  `mix(gray, col, 0) * 0.16` —— 背景（扫描环/光柱/网格）也一起去色，所以在 HUD 页
  任何彩色 3D 元素都只能渲染成灰白。这就是「环显得纯白单调」的根因，不是 shader 问题。
- 修法：合成通道对「背景像素」按色度保留颜色 —— `bgMask = 1 - tColor.a`
  （装甲写 alpha=1，背景 ≈0）+ `smoothstep(0.035,0.12,chroma)`，`s = max(uSurface, keep)`。
  战甲表面仍被压成线稿，背景环保住亮度和色相。
- 扫描环 shader：核心 `exp(-b*b*90)` 白热、辉光 `exp(-b*2.2)` 冷青；主色 = 0x38D8FF
  lerp 线色 30%（默认白线时也保持色彩个性，取色器仍能带偏）；`uDir` 按速度符号翻转
  渐变方向，`uHot ∝ |速度|` 折返时熄灭。
- 环体高度 0.55 → 0.13，加 `vFace` 掠射淡出（否则从下方看圆柱内壁糊成一整片圆盘）。
- 调试经验：页面用 `mix-blend-mode: screen` + iframe，像素采样必须按投影坐标定位；
  早期多次量错区域得出"颜色没生效"的错误结论，实际是 `uSurface` 去色。

## 流光改渐变 + 反浩克头部修复（a492a5a）

**头部没渲染的根因**：`js/showcase7/main.js` 的 `JUNK = /Plane|CreationNulCrew|IK_char_/i` 宽匹配。
反浩克的装甲部件大量叫 `Plane002` / `Plane004` / `Plane010`…，其中 `Base_HumanHead` 下的
`Plane002` / `.001` / `.006` / `.008` / `.036` 就是整个头（7755 tris），肋甲 `Plane004`(18719)、
骨盆 `Plane006`(9150)、上臂 `Plane009`、前臂 `Plane014`、大腿 `Plane015/016`、小腿 `Plane010/013`
也一并被隐藏 —— 等于砍掉 51k tris 半个身子。改成 `^Plane$|CreationNulCrew|IK_char_`：
MK VII 里被过滤的仍只有地面片 `Plane`(2 tris)、`CreationNulCrew_*`、`IK_char_*`，行为不变。

**流光生硬的三条原因**（showcase7 与 EdgePass 同病）：
1. `fract(vUv.y * 1.35 - …)` 频率非整数 → 上下接缝亮度突变；
2. 亮核 `smoothstep(0.075, 0.012)` 只有 6% 屏高，边沿近乎阶跃；
3. 拖尾只覆盖 ~42% 高度，其余是死黑 → 视觉上就是「一条亮杠在扫」。

**新配方（两处统一）**：带心单向扫过、两端都在画外（无接缝跳变）
```glsl
float bandY = mix(-0.55, 1.55, fract(uTime * speed / 2.1));  // ÷2.1 保持原速度语义
float dz = vUv.y - bandY;
float below = exp(-max(dz,0.0) * 3.4);   // 已扫过（下）：长余晖
float above = exp(-max(-dz,0.0) * 8.0);  // 未扫到（上）：短前缘
float pulse = mix(below, above, step(0.0, -dz)) * uFlow;
```
showcase7 峰值从 ~3.1× 收到 ~2.15×（`1.30 + 0.85*pulse`）；EdgePass 另加
`alive = smoothstep(0.0, 0.05, uFlowSpeed)`，速度滑到 0 时不留下底部死光。
showcase7 的 `uFlow` 改为每帧朝目标缓动（`dt*6.5`，约 0.4s），开关流光不再闪一下。

## MK7 拆解改成零件级（1b2f15b）

**为什么不用 gltf-exploder**：它的文档「数模图要求」写明——需要独立位移的零件在建模时必须
是独立 Mesh，"如果整个模型在导出时被合并为一个对象，插件将无法识别内部零件"。而 mk7 用的
`armor2.glb` 就是单块蒙皮网格，`irobny2` 的 736 个 node 全是骨骼；引入它只会得到"1 个零件整体平移"。
另外它自带 scene/camera/renderer/UI/补光，与本页「法线通道 + 深度通道 + 自定义合成」的线条管线
和自绘 HUD 冲突，还要 extra vendor。**根因不在爆炸算法，在拆分单元。**

**改造前后**：`segment.js` 洪水填充本来就算出 380 片连通域甲片，但阶段 4 又按 7 个区域聚合，
拆解时整条手臂 / 整个躯干壳作为一个刚体平移，断口一露就是「撕烂」。

新流程（segment.js 阶段 4.4→6）：
1. 岛屿保留为「单元」（跨区域大岛仍走折痕 ICM 切段）；
2. 每单元算面积加权质心 + 面积加权法线（`area[]` 新增，= 叉积模长 × 0.5）；
   法线与水平径向点积 < 0 就翻转（内衬件法线朝内会往身体里钻）；
3. 合并成零件：按面积降序当种子，同区域 + 质心 < `CELL*1.6`（CELL = 0.17H）+ 朝向点积 > 0.32；
   **三角形数 < 70 的碎屑无条件并入最近种子**（跨区域也并），否则拆开是一堆白点；
4. 实测 380 → 33 个零件。

main.js 侧：
- 脱开方向 `dir = normal*0.58 + 水平径向*0.42 + 区域朝向*0.12`，`dir.y` 下限 -0.4（脚底件不许垂直下坠）；
- 位移 `H * (0.072 + 0.112 * rNorm^1.4)`，`rNorm = |center-(0,0.55H,0)| / 0.62H` 且 clamp 0.9；
  径向**只取水平分量**——带上高度会让脚部件的径向接近垂直向下，整只脚掉出画面；
- 每片绕「dir × up」掀开 2–7°，配 `Quaternion.slerp(identity, quat, t)` 补间（tick 里 `m.quat` 分支）；
- stagger 改为 `(1 - y/H)*0.74 + def.stagger*0.16`：**自上而下**卸甲（旧版 helmet 0.50 是最后才走）；
- 相机：`splitZoom 1.40`、`splitTargetY 0.50`（原 1.45 / 0.64）。

**验证**：33 零件、90fps（与 7 块时相同）、boot 878ms（含切分）、组装态无缝、拆→合往返 t 归 0、
mk7-tiny / ironman-hud / jarvis-console / index 全回归正常。可调旋钮：`CELL`（粒度）、
位移系数 0.072/0.112、`splitZoom`。
**残余局限**：模型本身没有内骨骼/线路，拆开后内部是空的 —— 资产问题，换库也补不了。

## 扫描环「卡顿 + 两环不协调」修复（0cdd4dc）

`js/showcase7/main.js` 的 bgFx 垂直扫描环（mk7.html 与 ironman-hud.html 共用）：
- **卡顿根因**：`0.5 - 0.5*cos(w)` 纯余弦驱动，折返点速度趋零，环在顶/底「停留」近 0.5s
  才起步。改为 **0.78 三角波 + 0.22 余弦** 混合：全程近匀速、只在折返处轻柔化。
  实测 90fps 下逐帧位移中位 0.0068、最低 0.0053（仅低 22%，旧版会掉到 0）。
- **两环不协调根因**：主环 speed .85 / phase 0、副环 speed .55 / phase 2.2，速度不可通约 →
  两环各自乱漂、来回对穿。改为**同速 1.0、固定相位差 -0.62**：全程同向同行保持固定间距，
  在折返处自然汇合再展开（配对扫描的「呼吸」感）。
- 周期 7.4s → 6.28s 一个来回。
- HUD 皮肤（`skin=hud`）舞台上下都留了 HUD 边，`max` 从 1.98 收到 **1.80**，否则环在最高点
  被舞台沿硬切出断面；mk7 独立页保持 1.98（环能扫过头顶）。
- 关键读法：`state.time` 决定相位；调参入口是 push 进 `bgFx.rings` 的 `min/max/speed/phase`。

## 反应堆光斑：位置修正 + 环形不再被胸甲拉歪（fe22963）

`js/showcase7/main.js` 的 core glow（mk7.html / jarvis-console / ironman-hud 共用）两处根因：
1. **位置**：锚点 x 以前恒取包围盒中心 `cx`，从正中打射线。反浩克舱口在模型中线偏左
   （首页实测比例 x=-0.0155·H、y=0.742·H），正中射线先命中凸起胸甲 → 吸附错点。
   新增 `coreX` 配置 + `?corex=` 参数，锚点 x = cx + coreX·H；console 与 mk7-tiny 的
   反浩克入口传 `corex=-0.0155&corey=0.742`。实测落点 (-0.030, 1.447, 0.287)，正确。
2. **环不在一个平面**：旧版 `r = distance(surfacePoint, anchor)/R` 是球面距离，胸甲每处起伏
   都改变半径 → 环被拉歪。改为**平面投影**：视线与舱口平面（uCoreNrm）求交，`r` 在平面内量，
   环恒为正圆；离面距离只做粗遮挡 `smoothstep(R*corew, R*corew*0.35, along)`
   （手臂/抬起的护胸挡光，轻度起伏不参与）。`?corew=` 可调（默认 1.1）。
3. 平面法线取法：锚点 + 周围 4 点（±0.85R）各打一条前向射线，把命中面法线（经
   `Matrix3.getNormalMatrix` 转世界）求和归一化。tick 里 `applyAxisAngle` 跟随模型自转。
4. 曾试过「面内半径 + 高斯离面衰减」（gaussian wall），反浩克舱口有凸起坑沿，
   外晕被切在坑沿上、光斑变多边形；平面投影 + 粗遮挡没有这个问题。
5. 参数：corex / corey / corez / corer / corew。
